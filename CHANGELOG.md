# Changelog

Все заметные изменения TunnelManager фиксируются в этом файле.

## 1.2.0 (2026-10-02)

### Изменения в поведении
- Включённые туннели восстанавливаются после выхода из приложения и повторного запуска (раньше выход выключал их).
- Если процесс туннеля неожиданно завершился, туннель остаётся включённым и перезапускается с нарастающей паузой (2–60 с), о чём сообщает уведомление. Раньше он молча выключался.
- Редактирование работающего туннеля перезапускает его с новыми параметрами, а не выключает.
- Проверка TLS-сертификата локального HTTPS-сервиса по умолчанию пропускается только для локальных адресов (`localhost`, `127.0.0.0/8`, `::1`). Для адресов в сети она включена; галочка в форме следует за хостом, пока её не изменить вручную. Сохранённые туннели и явный выбор не меняются.
- Субдомен LocalTunnel проверяется по правилам сервера (4–63 латинских букв и цифр, дефисы внутри) уже в форме, а слишком длинный не обрезается молча. Для Cloudflare субдомен больше не сохраняется — он там не используется.
- Отказ сервера localtunnel (например, 403 «Invalid subdomain») показывается ошибкой с причиной вместо бесконечных повторов.
- Фильтр «Порт закрыт» заменён на «С проблемами»: он показывает и предупреждения, и ошибки.
- Тема по умолчанию следует системной; выбор кнопкой по-прежнему сохраняется.

### Безопасность
- Electron обновлён до 43.7.7 (исправлены уязвимости песочницы и кэша preload), уязвимые транзитивные зависимости обновлены; CI проверяет `npm audit`.
- `cloudflared` запускается через надзирателя и завершается вместе с приложением, даже если оно упало или было убито — раньше туннель продолжал открывать локальный порт в интернет.
- IPC-запросы принимаются только от главного фрейма окна приложения; внешние ссылки открываются только по `http(s)` и без учётных данных в адресе.
- Настройки, аргументы операций с туннелями и импортируемые файлы строго проверяются (белый список настроек, типы, размер файла до 1 МБ, не больше 1000 записей).
- Число соединений, которое запрашивает сервер localtunnel, ограничено 10.
- `cloudflared` скачивается только с `github.com` по ссылке из того же ответа API, что и контрольная сумма.

### Исправлено
- LocalTunnel: отказ туннельного порта больше не роняет главный процесс, туннель переподключается.
- LocalTunnel: сброс соединения больше не размножает соединения.
- LocalTunnel: заголовок `Host` подменяется во всех запросах keep-alive соединения, а не только в первом; зависание после сброса локального соединения устранено.
- LocalTunnel: сервер, приславший заголовки и замолчавший, больше не подвешивает запуск; неудачное переподключение закрывает туннель для перезапуска.
- Cloudflare: тайм-аут запуска 60 с; причина завершения `cloudflared` показывается на карточке; `--no-autoupdate`; IPv6-адреса в URL.
- Cloudflare: счётчик запросов берётся из метрик `cloudflared` (раньше он не считал настоящие запросы и реагировал на слова в логе).
- Причина неудачного запуска остаётся на карточке, а не сменяется «Не активен».
- Во время повторных попыток подключения переключатель остаётся включённым, карточка показывает предупреждение.
- Быстрое выключение и включение, а также остановка во время скачивания `cloudflared` больше не ломают последующий запуск.
- Проверка порта для `localhost` учитывает и `127.0.0.1`, и `::1` (ложное «порт недоступен» для IPv6-серверов).
- Импорт не падает на `null` в файле, понимает BOM и сообщает о битом JSON; версия в файле экспорта берётся из версии приложения.
- Ошибки всех действий окна показываются уведомлением с понятным текстом; Esc закрывает форму; «Скопировать все логи» сообщает о журнале; плашка «с проблемами» скрыта при нуле.
- Нет мигания светлой темы при запуске; на Windows задан AppUserModelID для системных уведомлений.
- Окно больше не показывает устаревшее состояние, если обновления из main-процесса пришли не по порядку (удалённая карточка не возвращается, ошибка запуска не видна при включённом переключателе).

### Добавлено
- `cloudflared` раз в неделю сверяется с последним релизом и обновляется.
- Переменная окружения `TUNNEL_MANAGER_LT_SERVER` — собственный сервер localtunnel вместо `https://loca.lt`.

### Производительность
- Запросы LocalTunnel считаются по разобранным заголовкам, а не регулярным выражением по всему трафику (на теле 200 МБ: ~655 мс → 6–10 мс).
- Логи пишутся по порядку, с ротацией (файлы до 5 МБ, не больше 5).
- Время работы отправляется только видимому окну; проверка портов шлёт только изменившиеся статусы.
- Карточки туннелей обновляются на месте, без пересоздания всего списка (сохраняются фокус и наведение).

### Разработка
- Модульные тесты (`npm test`, `node:test`), ESLint (`npm run lint`), pre-commit хук, запускающий оба.
- Сквозные тесты настоящего приложения (`npm run test:e2e`) с фейковыми серверами LocalTunnel и Cloudflare, в том числе против собранного приложения (`E2E_APP_EXECUTABLE`).
- GitHub Actions вместо Travis: линтер, модульные тесты и `npm audit` на Ubuntu и Windows, сквозные тесты на Ubuntu и Windows.
- Логика туннелей вынесена из `main.js` в `lib/TunnelManager.js`.

## 1.1.0 (2026-09-03)

### Безопасность
- Добавлена строгая политика `Content-Security-Policy` для окна приложения (`default-src 'self'`, `connect-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`).
- Все интерактивные элементы переведены с инлайновых `onclick`-обработчиков на `addEventListener`, что совместимо со строгим CSP (ранее CSP тихо блокировал закрытие модальных окон).
- Ответ туннель-сервера (LocalTunnel) теперь проверяется на допустимую схему (`http`/`https`) перед тем как публичный URL попадёт в интерфейс.
- Навигация окна (`will-navigate`) ограничена собственным `index.html` приложения вместо любого `file://`-адреса.
- Из зависимостей удалён неиспользуемый пакет `cloudflared` (загрузка и проверка бинарника реализованы отдельно, в `lib/CFTunnel.js`).
- Устранены известные уязвимости транзитивных зависимостей `electron-builder` (`brace-expansion`, `fast-uri`, `js-yaml`, `@xmldom/xmldom`) через `npm audit fix`.
- Убран дублирующийся `yarn.lock` — проект использует единственный лок-файл `package-lock.json` (npm).

### Изменено
- Полностью обновлён визуальный дизайн интерфейса: новая цветовая палитра, современная типографика, панель быстрой статистики, доработанная тёмная тема, анимации и состояния фокуса для доступности.
- Модальные окна теперь закрываются по клику вне окна и по клавише `Esc`, а не только по кнопке.
